# Tasks — mobile app (iOS & Android)

Expo SDK 58 · Expo Router (native tabs) · TanStack Query · same `/api/v1` as the web app.

| Screen | What it does |
|---|---|
| My tasks | Assigned to me (due chips) / To review; counts on top |
| Projects → project | Tasks grouped by status; Everyone / Mine / Unassigned; **+** new task |
| Task | Workflow buttons (comment / attachment rules applied), people, priority, due date, tags, description, checklist, files (camera, photos, documents — open / share), comments; ⋯ watch, email reminder, bin |
| Period | A routine run (e.g. *November 2026 · Month-end close*): progress and its tasks |
| Alerts | Notifications (badge on the tab); tap opens the task / period |
| Me | Profile, change password, sign out (stops push to this phone) |

The sign-in token is kept in the phone's secure storage (Keychain / Keystore). New accounts are
asked to set their own password first, as on the web.

## Run it on your phone (development)

Push notifications and the native modules need a **development build** (Expo Go cannot receive
remote push on Android).

```bash
cd mobile
npm install
cp .env.example .env            # EXPO_PUBLIC_API_URL=http://<your computer's LAN IP>:8000
npx eas-cli@latest login        # your Expo account
npx eas-cli@latest init         # links the app, writes extra.eas.projectId into app.json (needed for push)
npx eas-cli@latest build --profile development --platform android   # or ios; install the build on the phone
npx expo start --dev-client     # then open the app on the phone
```

The backend must listen on the network for a phone to reach it: `php artisan serve --host=0.0.0.0`.
The server address can also be changed on the sign-in screen ("Server: … · change").

Quick look in a browser (no push, no camera): `npx expo start --web`.

## Builds and releases

`eas.json` profiles:

| Profile | For | API address (`EXPO_PUBLIC_API_URL`) |
|---|---|---|
| `development` | dev client on your phone | your computer on the LAN |
| `preview` | internal testers (Android APK, iOS ad-hoc) | the production HTTPS address |
| `production` | App Store / Play Store | the production HTTPS address |

**Set the production address** in `eas.json` (`https://tasks.example.com` is a placeholder) to the
public HTTPS hostname of the server (the Cloudflare Tunnel hostname — see `deploy/DEPLOY.md`).

Release (like mess_soft's Android release): push a tag and GitHub Actions builds both apps on EAS
and submits them to the stores:

```bash
git tag -a mobile-v1.0.0 -m "What changed"
git push origin mobile-v1.0.0
```

Needs the repository secret `EXPO_TOKEN` (expo.dev → Account settings → Access tokens). Store
credentials (Apple App Store Connect API key, Google Play service account) are kept by EAS:
set them once with `npx eas-cli credentials` and `eas submit`.

**Push credentials:** iOS (APNs key) is created by EAS on the first iOS build. Android needs an
FCM v1 service-account key uploaded with `npx eas-cli credentials` (Android → Push notifications).
The server needs nothing extra; for Expo's enhanced push security, set `EXPO_ACCESS_TOKEN` in the
server's `.env`.

## Notes

- `src/lib/types.ts`, `format.ts` and `labels.ts` mirror the web app's (`frontend/src/lib`) — keep them in step when the API changes.
- Never edit `ios/` or `android/` by hand (they are generated by `npx expo prebuild` / EAS and are gitignored); configure native settings in `app.json`.
